# ARU Event Pass

ระบบลงทะเบียนและเช็กอินกิจกรรมขององค์การนักศึกษา มหาวิทยาลัยราชภัฏพระนครศรีอยุธยา

อัปเดตเอกสาร: **12 พฤศจิกายน 2569 (2026-11-12)** ผู้ดูแลแจ้งว่าเริ่มใช้งานจริงแล้ว เอกสารนี้อ้างอิงโค้ดใน repository และ migration ถึง **036_match_attended_passcodes.sql** ไม่ใช่การยืนยันว่า production ติดตั้งครบแล้ว

## คู่มือใช้งานปัจจุบัน

### บัญชีนักศึกษาและการนำเข้า

แอดมินเปิด **บัญชีผู้ใช้ → นำเข้าทะเบียนนักศึกษา** รองรับ CSV UTF-8 (comma หรือ semicolon) และ Excel `.xlsx` โดยอ่านชีตแรก มีตัวอย่างคอลัมน์ ตัวอย่างข้อมูล 5 แถว และไฟล์ CSV ตัวอย่างให้ดาวน์โหลด

| ข้อมูล | หัวคอลัมน์ที่ใช้ได้ | ตัวอย่าง |
| --- | --- | --- |
| รหัสนักศึกษา | student_id / รหัสนักศึกษา | 16915039 |
| ชื่อเต็ม | full_name / ชื่อ-นามสกุล | นายชวัลวิทย์ สถาปนพงษ์ |
| ชื่อแยกช่อง | คำนำหน้าไทย, ชื่อไทย, นามสกุลไทย | นาย, ชวัลวิทย์, สถาปนพงษ์ |
| คณะ | faculty / คณะ | คณะครุศาสตร์ |
| สาขา | major / สาขาวิชา | การศึกษาพิเศษและการสอนภาษาไทย (4 ปี) |
| หมู่ | class_group / หมู่เรียน / หมู่ | 1 |
| ชั้นปีปัจจุบัน | study_year / ชั้นปี | 1 |
| วันเกิด | birth_date / วันเกิด | 18/11/2550 หรือ 18112550 |
| โทรศัพท์ (เสริม) | phone / เบอร์โทรศัพท์ | 0812345678 |

เก็บรหัสนักศึกษาและโทรศัพท์เป็นข้อความเพื่อรักษาศูนย์นำหน้า ใช้ชื่อเต็มหรือชื่อแยกช่องอย่างใดอย่างหนึ่ง ชั้นปีรองรับ 1–8 และยังรองรับคอลัมน์รุ่น/ปีเข้าแบบเดิม แต่ควรระบุชั้นปีปัจจุบันให้ชัดเจน

นำเข้าแล้วสร้างบัญชีอัตโนมัติ ชื่อผู้ใช้เป็นรหัสนักศึกษา รหัสผ่านเริ่มต้นเป็นวันเกิด พ.ศ. 8 หลัก เช่น `18112550` บัญชีเดิมจะถูกข้าม ไม่เปลี่ยนรหัสผ่านเดิม การนำเข้าบัญชียังไม่เท่ากับการเข้าร่วมกิจกรรม

ระบบส่งรายชื่อทีละชุด เริ่ม 25 คน และลดขนาดเมื่อพบ timeout หากหยุดกลางทาง ให้นำเข้าไฟล์เดิมซ้ำได้ บัญชีที่สำเร็จแล้วจะถูกข้าม

### ลงทะเบียนออนไลน์

1. แอดมินเลือกกิจกรรม เปิด **รับสมัครและอนุมัติรายชื่อ** แล้วเปิดรับออนไลน์
2. ส่งลิงก์ `/register/<eventId>` ให้นักศึกษา
3. นักศึกษากรอกรหัสนักศึกษา ระบบตรวจบัญชีอัตโนมัติ หากมีบัญชีให้กรอกรหัสผ่านปัจจุบัน
4. หากไม่มีบัญชี จะแสดง **รหัสนักศึกษาไม่ถูกต้อง กรุณาตรวจสอบ** พร้อมคำแนะนำให้ติดต่อแอดมิน ไม่มีการสร้างบัญชีใหม่ผ่านหน้าสมัครออนไลน์
5. บัญชีเดิมทุกชั้นปีสมัครแล้วเข้ารายชื่อกิจกรรมและเปิด QR สแกนเข้างานได้ทันที ไม่ต้องรอ Passcode

สถานะหลังสมัครคือ **รอสแกนเข้างาน** ยังไม่ถือว่ามาร่วมจริง แอดมินสามารถผูกรายชื่อนักศึกษาทั้งหมดในระบบเข้ากิจกรรมล่วงหน้าผ่านปุ่มในหน้าจัดการกิจกรรมได้เช่นกัน

ใบสมัครเก่าที่ค้างในคิวยังจัดการได้ รวมถึงเลือกอนุมัติหลายรายการ ส่งกลับแก้ไข และยกเลิก นักศึกษาที่ถูกส่งกลับแก้ไขล็อกอินแล้วเปิดใบสมัครจากการ์ดกิจกรรมได้

### เครื่องลงทะเบียน iPad

แอดมินเปิด **ตั้งค่าเครื่อง iPad และช่องทางติดต่อ** สร้างบัญชีเครื่องที่ผูกกับกิจกรรม แล้วล็อกอินบัญชีเครื่องที่ `/kiosk`

นักศึกษากรอกรหัสนักศึกษาและรหัสผ่านบัญชีเดิม หากถูกต้องและกิจกรรม ACTIVE ระบบเช็กอินเป็น **กำลังเข้าร่วมกิจกรรม** ทันที หน้าจอแสดง QR ลิงก์หน้า Login ให้นักศึกษาสแกนด้วยมือถือและล็อกอินเอง จากนั้นเปิดบัตร QR สำหรับสแกนออกงานได้

QR บน iPad เป็นลิงก์เข้าเว็บ ไม่บรรจุรหัสผ่านหรือเซสชันนักศึกษา กด **คนถัดไป** เพื่อล้างหน้าจอ หรือระบบล้างผลหลัง 90 วินาที การออกรหัสผ่านเครื่องใหม่จะยกเลิกเซสชันเครื่องเดิม

### สแกนและ Passcode

| สถานะ | ความหมาย |
| --- | --- |
| REGISTERED | ลงทะเบียนแล้ว รอสแกนเข้างาน |
| ATTENDING | เช็กอินแล้ว กำลังเข้าร่วมกิจกรรม |
| COMPLETED | เช็กเอาต์แล้ว เข้าร่วมสำเร็จ |

สตาฟเลือกกิจกรรมและโหมดสแกนเข้า/ออกให้ตรงกัน ใช้งานกล้องผ่าน HTTPS หรือ localhost พร้อมอนุญาต Camera นักศึกษาปี 1 ใช้ URL ที่กำหนดหลังเช็กอิน

นักศึกษาปี 2 ขึ้นไปเข้าร่วมและสแกนออกได้แม้ยังไม่มี Passcode รหัสจะแสดงแก่นักศึกษาเมื่อสถานะสำเร็จ หากยังไม่มีจะแสดงรอจัดสรร

ตั้งแต่ migration 036 การจับคู่รหัสสำรองจะเลือกผู้ที่ ATTENDING หรือ COMPLETED เท่านั้น ให้ผู้เช็กเอาต์แล้วก่อน จากนั้นเรียงตามเวลาเช็กอิน การลงทะเบียนล่วงหน้าไม่ตัดรหัสสำรอง เมื่อเติม Passcode จะจับคู่ให้อัตโนมัติ หรือกดจับคู่ภายหลังได้ จุดสแกนออกจะลองจัดสรรรหัสสำรองที่เหลือให้ด้วย

### แก้ข้อมูลและส่งออก

- **จัดการกิจกรรม → แก้ไขข้อมูลกิจกรรม**: แก้ชื่อ สถานที่ ชั่วโมง และบันทึก เปลี่ยนสถานะกิจกรรม ลิงก์ปี 1 และแบนเนอร์ได้
- **รายชื่อนักศึกษาที่ลงทะเบียนกิจกรรมนี้ → ส่งออกรายชื่อ CSV**: ทุกสถานะของกิจกรรมที่เลือก ไม่ใช้ตัวกรองรายงานด้านบน
- **รายงานผู้เข้าร่วม → ส่งออกผู้เข้าร่วม CSV**: ตามตัวกรอง พร้อมสถานะ เวลาเข้า–ออก และผู้เช็กอิน/เช็กเอาต์
- **รับสมัครและอนุมัติรายชื่อ → ส่งออก CSV**: รายชื่อในคิวของกิจกรรม หรือเฉพาะรายการที่เลือก
- **แก้สถานะ**: เฉพาะแอดมิน ต้องระบุเหตุผล เก็บข้อมูลก่อน–หลังในประวัติ ย้อนเป็น REGISTERED จะล้างเวลาเข้า–ออก ย้อนเป็น ATTENDING จะล้างเวลาออก หากไม่มีเวลาที่จำเป็นจะใช้เวลาบันทึก ยกเลิก QR เดิมและคง Passcode ที่จับคู่แล้วไว้

## อัปเดตระบบที่ใช้งานจริง

1. สำรองฐานข้อมูลและบันทึกเวอร์ชันเว็บที่ใช้อยู่ก่อนเปลี่ยนแปลง
2. ตรวจ migration ที่ production เคยรันจริง ห้ามเดาจากเลขไฟล์ใน repository รันเฉพาะไฟล์ที่ยังไม่เคยรัน เรียงตามเลขถึง 036
3. ทดสอบการเปลี่ยนแปลงกับฐานข้อมูลทดสอบก่อน และเลือกช่วงไม่รบกวนการสแกนหน้างาน
4. ติดตั้ง migration ที่เว็บรุ่นใหม่ต้องใช้ แล้ว deploy เว็บ ให้เครื่องสตาฟและ iPad รีเฟรช
5. ตรวจด้วยบัญชีทดสอบ: ล็อกอิน สมัครกิจกรรม สแกนเข้า–ออก iPad จับคู่ Passcode ส่งออก CSV และบันทึกสถานที่
6. หากมีปัญหา ให้เก็บชื่อ RPC และข้อความ Response โดยไม่ส่ง token หรือรหัสผ่าน การย้อนเว็บไม่ย้อนฐานข้อมูลโดยอัตโนมัติ ต้องตรวจความเข้ากันได้ก่อน

เอกสารนี้ไม่ได้รัน migration หรือ deploy production ให้ และไม่ควรรัน SQL พิมพ์เขียวเก่าทับข้อมูลจริง

## พัฒนาในเครื่อง

ใช้ Node.js ที่ตรงกับ requirements ของ Next.js ที่ติดตั้ง ตรวจเวอร์ชันใน `package-lock.json`

```sh
npm ci
npm run dev
```

คัดลอก `.env.example` เป็น `.env.local` แล้วกำหนด `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` จาก project ที่ต้องการทดสอบ อย่าใช้ service-role key ในตัวแปร `NEXT_PUBLIC_*` หากไม่มีการตั้งค่า แอปใช้ Demo Mode ซึ่งข้อมูลอยู่ในเบราว์เซอร์และไม่ใช่ข้อมูลหน้างานจริง

```sh
npx tsc --noEmit
npm run build -- --webpack
```

ไฟล์ทดสอบ SQL อยู่ใน `supabase/tests/` ใช้ฐานข้อมูลทดสอบและตรวจ prerequisite ของแต่ละไฟล์ก่อนรัน บางชุดบันทึก flow รุ่นเก่าที่เปลี่ยนไปแล้ว ไม่ควรถือว่าทุกชุดผ่านกับ migration ล่าสุดโดยอัตโนมัติ

## อัปเดต Passcode 037 (2026-11-13)

รัน `037_safe_passcode_batches.sql` หลัง 036 แล้ว deploy เว็บใหม่ การแก้ไขเป็นฟังก์ชันเท่านั้น ไม่ลบหรือเปลี่ยนเจ้าของรหัสเดิม ปิดสิทธิ์เรียก process_qr_scan โดยตรง และหยุด trigger จ่ายรหัสเมื่อสถานะยัง REGISTERED รหัสเดิมที่เคยจัดสรรจะไม่ถูกคืนอัตโนมัติ

วาง 500 รหัสได้ในครั้งเดียว หน้าเว็บเพิ่มทีละ 50 รหัสและจับคู่ทีละ 25 คน แสดงจำนวนและความคืบหน้า ลดขนาดชุดเมื่อ timeout แต่หยุดเมื่อชุดเล็กที่สุดยังผิดพลาด ส่งรายการเดิมซ้ำได้โดยข้ามรหัสเดิม และกดจับคู่ต่อได้ หากมีการล็อกข้อมูลพร้อมกันอาจเหลือรายชื่อให้กดต่อ ชุดที่ยืนยันสำเร็จแล้วไม่ถูกย้อนเมื่อชุดถัดไปล้มเหลว ระยะเวลาจริงขึ้นกับ production

RPC admin_add_reserve_passcodes รับสูงสุด 100 รหัสต่อคำขอและไม่จับคู่ภายในคำขอเดียวอีกต่อไป เว็บรุ่นใหม่เรียก admin_match_passcodes_batch ต่อเนื่องหลังเพิ่มเสร็จ หากยังใช้เว็บเก่าให้รีเฟรชหลัง deploy; RPC จับคู่เดิมทำสูงสุด 25 คนต่อครั้ง
