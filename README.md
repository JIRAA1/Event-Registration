# ARU Event Pass

เว็บแอประบบลงทะเบียนและเช็กอินกิจกรรมสำหรับองค์การนักศึกษา มหาวิทยาลัยราชภัฏพระนครศรีอยุธยา

## เริ่มใช้งาน

1. ติดตั้ง Node.js 20 ขึ้นไป แล้วรัน `npm install`
2. เริ่มเว็บด้วย `npm run dev` และเปิด `http://localhost:3000`
3. ถ้ายังไม่ใส่ Supabase credentials แอปจะเปิด **Demo Mode** และบันทึกข้อมูลตัวอย่างในเบราว์เซอร์
4. เลือกเข้าสู่ระบบนักศึกษา / โหมดสตาฟ / ผู้ดูแลระบบ เพื่อทดลองแต่ละหน้าจอ

## เชื่อมต่อ Supabase Cloud

1. สร้าง Supabase project แล้วรันไฟล์ใน `supabase/migrations/` ตามลำดับเลขใน SQL Editor หากใช้โปรเจกต์เดิม ให้รันเฉพาะ migration ที่ยังไม่เคยรัน โดยเรียงตามเลข (โปรเจกต์ที่ตั้งค่าถึง `002` แล้ว ต้องรัน `003` ถึง `006`)
2. คัดลอก `.env.example` เป็น `.env.local` แล้วกรอก Project URL กับ publishable key จาก Project Settings → API Keys
3. ปิดและเปิด dev server ใหม่
4. ตรวจว่า `event_registrations` และ `event_passcodes` อยู่ใน publication `supabase_realtime` (migration เพิ่มให้เมื่อ publication มีอยู่แล้ว)

สร้างบัญชี ADMIN คนแรกครั้งเดียวใน SQL Editor โดยเปลี่ยน username, password และชื่อเป็นค่าที่ต้องการก่อนรัน จากนั้นเพิ่ม STAFF/ADMIN คนอื่นผ่านหน้า Admin:

```sql
alter table public.users alter column birth_date drop not null;

insert into public.users (student_id, password_hash, full_name, enrollment_year, birth_date, role)
values ('admin001', crypt('CHANGE-THIS-TO-A-STRONG-PASSWORD', gen_salt('bf')), 'ARU System Admin', 0, null, 'ADMIN');
```

ไฟล์ [`lib/sound.ts`](lib/sound.ts) จัดการ Web Audio Synthesizer และ `lib/supabase.ts` สร้าง Supabase client เมื่อมีค่าตั้งต้น

## บัญชีตัวอย่างใน Demo Mode

- นักศึกษา: รหัส `6801234` · วันเกิด `22062549`
- สตาฟ: เลือก “เข้าสู่โหมดสตาฟ”
- แอดมิน: เลือก “ผู้ดูแลระบบ”

ในหน้า Admin สามารถสร้างบัญชี STAFF หรือ ADMIN ได้ โดยฐานข้อมูลจะเก็บรหัสผ่านเป็น bcrypt hash และ RPC จะตรวจ admin session token ก่อนเพิ่มบัญชี

ฟอร์มลงทะเบียนหน้างานเลือกคณะและสาขาจากรายการ ARU ที่กำหนดไว้ใน `lib/aru-catalog.ts` แทนการพิมพ์เอง โดยอ้างอิงรายการหลักสูตรจาก [กองบริการการศึกษา ARU](https://www.aru.ac.th/regis/index.php?page=fieldstd) หน้ารายงานผู้เข้าร่วมกรองตามคณะ/สาขาและส่งออก CSV ได้

กล้องต้องเปิดเว็บผ่าน HTTPS หรือ `http://localhost` และอนุญาตสิทธิ์ Camera ในเบราว์เซอร์ หากเปิดจาก IP บนเครือข่ายผ่าน HTTP เบราว์เซอร์จะปิดกั้นการเข้าถึงกล้อง

ใน Demo Mode ช่องทดสอบ QR รับข้อมูลตัวอย่าง `{"e":"evt-aru-01","u":"stu-aru-6801234"}` ได้โดยไม่ต้องเปิดกล้อง

### เปิดใช้บัตร QR แบบใช้ครั้งเดียวบน Supabase

ก่อนเริ่มรอบกิจกรรม ให้รัน migration ถึง `018_session_bound_event_qr.sql` ตามลำดับ แล้วนำเว็บรุ่นนี้ขึ้นพร้อมกัน ให้นักศึกษาและสตาฟรีเฟรชหน้าที่เปิดค้างไว้ เพราะ migration นี้ปิดสิทธิ์เรียกคำสั่งสแกนแบบเดิมทันที

บัตรในโหมด Supabase มีอายุสูงสุด 60 วินาทีและต่ออายุขณะเปิดหน้าบัตร การเปิดบัตรครั้งแรกจะกำหนดเซสชันที่ถือสิทธิ์ หากต้องการใช้เบราว์เซอร์อื่น ให้กด “ย้ายบัตรมาเครื่องนี้” ระบบจะยกเลิก QR เดิมทุกกิจกรรมของบัญชีและเก็บสถานะการเข้าร่วมเดิมไว้

## ฟอร์แมต CSV

ไฟล์ CSV ให้ใช้แถวแรกเป็นหัวตาราง รองรับทั้งชื่อคอลัมน์ภาษาอังกฤษและภาษาไทย โดยเรียงคอลัมน์ตามนี้:

```text
student_id,full_name,faculty,major,class_group,study_year,birth_date,phone
รหัสนักศึกษา,ชื่อ-นามสกุล,คณะ,สาขาวิชา,หมู่เรียน,ชั้นปี,วันเกิด,เบอร์โทรศัพท์
```

ระบุชั้นปีปัจจุบันเป็นเลข 1–8 (รับเลขไทยได้) และวันเกิดรูปแบบ `วว/ดด/ปปปป` หรือเลข 8 หลัก ระบบรองรับไฟล์ CSV แบบ UTF-8 ที่คั่นด้วย comma หรือ semicolon หัวตาราง `enrollment_year` แบบเดิมยังนำเข้าได้ แต่แนะนำให้ใช้ `study_year` แทน

แอดมินเติม Passcode สำรองไว้ในกิจกรรม แล้วระบบจับคู่ให้อัตโนมัติตามชั้นปีปัจจุบันและปีการศึกษาปัจจุบัน ส่วนรุ่นปี 1 ใช้ QR check-in/check-out

## ขอบเขตการเชื่อมต่อ

Demo Mode เก็บข้อมูลใน local storage และรองรับ flow สำหรับสาธิต Student, Staff, Walk-in และ Admin
การเชื่อมต่อ Supabase ในชุดเริ่มต้นเปิดใช้งาน login RPC, scan RPC และ Realtime subscription; ก่อนนำไปใช้จริงควรเพิ่ม RPC สำหรับโหลด/จัดการข้อมูลกิจกรรม และเปลี่ยน custom login ให้ผูกกับ Supabase Auth หรือ server session ที่ตรวจสอบได้ เนื่องจาก anon key เป็นข้อมูลสาธารณะและไม่ควรใช้ user ID จาก browser เป็นหลักฐานสิทธิ์

## สมัครรายกิจกรรมและเครื่องลงทะเบียนหน้างาน

หลังติดตั้ง migration 001–031 และนำเว็บขึ้น ให้เลือกกิจกรรมในหน้าแอดมิน เปิด **รับสมัครและอนุมัติรายชื่อ** แล้วกด **เปิดรับออนไลน์** คัดลอกลิงก์ `/register/<eventId>` สำหรับประชาสัมพันธ์ กิจกรรมเริ่มต้นด้วยการปิดรับออนไลน์ การปิดรับออนไลน์ยังอนุญาตให้ iPad ส่งคำขอในกิจกรรมที่ยังไม่ปิดได้

ผู้สมัครออนไลน์รายใหม่จะได้รับการ์ดชื่อผู้ใช้และรหัสผ่านวันเดือนปีเกิด พ.ศ. 8 หลัก เช่น 01012549 ทันทีหลังสมัคร เมื่อล็อกอินจะเห็นสถานะ **รอยืนยันเข้าร่วมกิจกรรม** ผู้มีบัญชีเดิมใช้รหัสผ่านปัจจุบัน ปี 1 เข้าร่วมได้ทันที ส่วนปี 2 ขึ้นไปสมัครแล้วเข้ารายชื่อกิจกรรมและเปิด QR ได้ทันที เติม Passcode ภายหลังได้ แอดมินเลือกอนุมัติหลายใบสมัครพร้อมกันได้ หากรหัสสำรองยังไม่พร้อม สามารถเติมและจับคู่ภายหลังได้ ปุ่มส่งออก CSV ใช้รายชื่อในคิวของกิจกรรมที่เปิดอยู่ เมื่อเลือกรายการจะส่งออกเฉพาะใบสมัครที่เลือก

เมื่อนักศึกษาได้รับคำขอแก้ไขใบสมัครออนไลน์ ให้ล็อกอิน Event Pass แล้วกด **เปิดใบสมัครเพื่อแก้ไข** ใต้ชื่อกิจกรรม หลังส่งข้อมูล ใบสมัครเดิมจะกลับเข้าคิวรอยืนยัน

ใน **ตั้งค่าเครื่อง iPad และช่องทางติดต่อ** ให้บันทึกลิงก์ HTTPS สำหรับติดต่อแอดมิน และสร้างบัญชีเครื่องสำหรับกิจกรรม เปิด `/kiosk` บน iPad แล้วลงชื่อเข้าใช้ด้วยบัญชีเครื่อง คิวระบุที่มา “หน้างาน” และเลขคำขอ แอดมินสามารถส่งกลับให้แก้ไข อนุมัติ หรือยกเลิก หลังอนุมัติให้ผู้ใช้สแกน QR ด้วยมือถือและบันทึกข้อมูลของตนก่อนกด **เสร็จแล้ว · คนถัดไป** การออกรหัสผ่านเครื่องใหม่จะยกเลิกเซสชันเครื่องเดิม

Migration 021 ปรับเลขไทยเป็นเลขอารบิกและตัดช่องว่างรอบรหัสนักศึกษาที่มีอยู่ โดยคงศูนย์นำหน้า หากข้อมูลเก่าชนกันหลังปรับรูปแบบ SQL จะยกเลิกทั้ง migration ให้แอดมินตรวจสอบเจ้าของบัญชีก่อนรันใหม่

นำเข้าบัญชีนักศึกษาล่วงหน้าได้ที่ **บัญชีผู้ใช้ → นำเข้าทะเบียนนักศึกษา** ใช้ CSV UTF-8 หรือ Excel .xlsx (ชีตแรก) มีตารางตัวอย่างคอลัมน์ ปุ่มดาวน์โหลดตัวอย่าง CSV และแสดงตัวอย่างข้อมูล 5 แถวแรกก่อนนำเข้า รองรับหัวตารางคำนำหน้าไทย ชื่อไทย นามสกุลไทย หมู่ รุ่น และวันเกิดแบบ 18/11/2550 เบอร์โทรเป็นช่องเสริม รหัสนักศึกษาที่มีอยู่จะถูกข้าม บัญชีใหม่เข้าสู่ระบบด้วยรหัสนักศึกษาและรหัสผ่านวันเกิด พ.ศ. 8 หลัก แล้วเลือกกิจกรรมจาก **กิจกรรมที่เปิดรับสมัคร**

การนำเข้าทะเบียนส่งทีละชุด เริ่มชุดละ 25 คนและลดขนาดอัตโนมัติเมื่อฐานข้อมูลหมดเวลา หน้าจอแสดงจำนวนแถวที่ยืนยันผลแล้ว หากหยุดกลางทางให้นำเข้าไฟล์เดิมอีกครั้ง บัญชีที่สำเร็จแล้วจะถูกข้าม Migration 029 ลดงานเข้ารหัสรหัสผ่านสำหรับบัญชีเดิม

หลัง migration 031 บัญชีเดิมสมัครออนไลน์แล้วเปิด QR สแกนเข้างานได้ทุกชั้นปี ใบสมัครออนไลน์สถานะรอยืนยันที่มีบัญชีแล้วในกิจกรรมที่ยังเปิดจะย้ายเข้ารายชื่อกิจกรรมด้วย เครื่อง iPad ให้ผู้เข้าร่วมกรอกรหัสนักศึกษาและรหัสผ่านเพื่อเช็กอินเป็นสถานะกำลังเข้าร่วมกิจกรรม จากนั้นแสดง QR ลิงก์ Event Pass สำหรับล็อกอินบนมือถือ ปุ่มคนถัดไปและเวลาล้างข้อมูล 90 วินาทีจะล้างข้อมูลผู้เข้าร่วมจากหน้าจอเครื่อง

เติมรหัสผ่านเมนูจัดการ Passcode แล้วระบบจับคู่ให้ผู้ที่ยังไม่มีรหัสโดยอัตโนมัติ หรือกดจับคู่รหัสให้รายชื่อที่รอได้ ผู้ที่เช็กเอาต์ก่อนมีรหัสจะแสดงรอจัดสรร Passcode และเห็นรหัสเมื่อแอดมินจับคู่แล้ว รายงานผู้เข้าร่วมส่งออก CSV ตามตัวกรองได้ พร้อมสถานะ เวลาเข้าออก และแหล่งเช็กอินจากเครื่อง iPad
